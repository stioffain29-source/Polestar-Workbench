# 1.3 — Report logic maps (end-to-end trace)

**Audit date:** 2026-08-26  
**Method:** Code-traced pipeline paths (preview == PDF invariant enforced throughout)

Each map follows: **DB rows → relevance filter → report window → dataset builder → classifier → prose → preview → PDF**

## Shared primitives (all topic reports)

| Stage | Authority | Notes |
| --- | --- | --- |
| DB load | `incidents` table + `relevance_status` | Cargo: API/headless loads with `includeIrrelevant`; scope re-applied downstream |

| Prose precedence | `topicProseResolution.ts` | Analyst edit → AI → deterministic draft |
| Thin content trap | `incidentClassifier.ts` + `draftReportProse.ts` | "Data quality issue" = coarse classifier plurality + thin ReportPack (see memory) |

## Flashpoint Watch — **HIGH priority**

| Surface | Incident set | Selector |
| --- | --- | --- |
| KPI cards / counts | `selectFlashpointUsable().enriched` | Single selector |
| Activism / Unrest tables | Same set, bucket split | `enrich()` → activism vs unrest |
| Charts (country bar, trend) | Same usable set | Derived from enriched |
| Fast Facts | `filterTopicReportIncidents` then overlaps usable | Must align — flashpoint merges `flashpoint` + `protests` buckets |
| Prose (exec, whatMatters, …) | `buildFlashpointReportDataset` | Uses same `selectFlashpointUsable` |
| Related Incidents (max 6) | Cross-section dedupe from table caps | `FLASHPOINT_RELATED_ROW_CAP = 6` |
| PDF | `exportFlashpointReportPdf` | Calls `buildFlashpointReportDataset` |

### `selectFlashpointUsable` funnel (single source of truth)

```
rawWindow (in-window, flashpoint+protests)
  → off-topic (isTopicRelevant)
  → kinetic-only DROP
  → court-only DROP
  → out-of-scope-crime DROP
  → dedupeByTitle
  → weak-novelty DROP
  → weak-operational DROP (unless upcoming signal outside period)
  = FINAL enriched set (counts + prose + tables)
```

### Known divergence / risk points

| Issue | Cause | Verify with |
| --- | --- | --- |
| Count ≠ prose contradiction | Historical: different subsets for KPI vs narrative | `proveFlashpointSelection.ts`, parity tests |
| Weak-ops slop (sports strike, market rally) | Survives relevance, caught at weak-operational — or leaks if pattern gap | `diagnoseFunnel.ts`, client-flagged patterns |
| Period totals vs event dates | Future-dated announcements use stated event date | `buildFlashpointReportDataset` forecast logic |

**Key file:** `artifacts/workbench/src/lib/flashpointReportDataset.ts`

## Cargo Watch — **HIGH priority**

| Surface | Incident set | Gate |
| --- | --- | --- |
| Page / monitor | `classifyScope` in `cargoAnalysis.ts` | Display authority; reconciles banner buckets |
| Report window | `filterTopicReportIncidents(..., "cargo_watch")` | Applies `isCargoInScope` |
| Pattern model / charts | `buildCargoPatternModel` | Same windowed set |
| Validation | 10-check hard gate | `cargo-report-validation-gate` tests |
| Slop | `CARGO_SLOP_EXCLUDE` in `cargoSlop.ts` | Mirrored in relevance + `classifyScope` |

### Two-layer model (load-bearing)

1. **Ingest relevance** — topic-level; stamps `relevance_status`
2. **Display scope** — `isCargoInScope` / `hasGenuineCargo` / `isCargoNoise` — can drop rows already marked relevant

**Risk:** Slop filter + validation gate must stay coupled; fixing one without the other produces publish failures or visible slop.

**Key files:** `cargoPatternModel.ts`, `cargoAnalysis.ts`, `lib/relevance/src/cargoSlop.ts`

## Energy / Fertiliser / Data Centres — Medium (thin-content risk)

| Surface | Path |
| --- | --- |
| Fast Facts | Generic `filterTopicReportIncidents` + `topicFastFacts` |
| Prose | Generic `draftTopicReportProse` via `topicProseResolution` |
| Classifier | `classifyIncidentType` — coarse buckets → "Data quality issue" note |

**Thin-content triggers:**

1. ReportPack returns single sentences (compare to Fuel/Shipping multi-para structure)
2. Classifier dumps plurality into `"Other <topic> incident"` → Fast Fact apology
3. Plural-regex trap: `outage\b` misses `outages` → false "Other" plurality

**Reference:** `.agents/memory/report-thin-content-diagnosis.md`

### Country pipeline (distinct from topic reports)

```
DB (90d, includeIrrelevant)
  → countryMatch guards (frontend authority — NOT relevance_status)
  → build*ReportDataset (country-engine)
  → structured brief sections + operating risk prose
  → exportCountryReportPdf
```

**Critical:** Country reports **ignore** server `relevance_status` for geography — render-time guards are the fix layer for Indonesia slop.

**Scripts:** `countryReportData.ts`, QA workflow `country-brief-sweep`

## Thin-content diagnostic checklist

When Steve flags "Data quality issue" or thin prose:

- [ ] Count incidents in report window after relevance (not raw topic table)
- [ ] Run classifier on that window — check "Other" plurality
- [ ] Inspect `draftReportProse.ts` pack for topic — compare section count to Shipping/Fuel
- [ ] Check plural-regex on classifier tokens (`outages?` not `outage\b`)
