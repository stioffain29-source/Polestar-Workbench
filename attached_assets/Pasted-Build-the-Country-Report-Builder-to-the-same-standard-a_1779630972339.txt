Build the Country Report Builder to the same standard as the standard Polestar Workbench reports.

Scope:
Country reports are separate from the Reports page, but they must use the same report product standards for:
- fonts
- branding
- colours
- prose
- PDF export quality
- chart styling
- card styling
- table styling

Apply this to:
- Papua
- Papua New Guinea
- any other country report generated by the Country Report Builder

Do not move country reports into the standard Reports page. They remain a separate country-report workflow.

1. Fonts

Roboto is mandatory.

Use Roboto across country report preview and PDF export:
- Cover title: Roboto Bold
- Section headings: Roboto Bold
- Body copy: Roboto Regular
- Card labels: Roboto Medium or Roboto Bold
- Card values: Roboto Bold
- Table headers: Roboto Bold
- Table body: Roboto Regular
- Footer: Roboto Regular

Do not allow jsPDF or browser defaults to fall back to Helvetica.
Do not claim Roboto is used unless the exported PDF actually uses Roboto.

2. Brand colours

Use only the approved Polestar colours:

- Midnight Blue: #0b0a3d
- Electric Blue: #465bff
- Dusk Gray: #363636
- Polar Gray: #e2e2e2

Do not use:
- #0B0B3D
- #4655FF
- #303030
- #E2E2E2

Country reports should visually belong to the same Polestar product suite as:
- Fuel Watch
- Fertiliser Watch
- Cargo Watch
- Shipping Watch
- Flashpoint
- Energy Watch

3. Cover and layout standard

Country report covers should use the same Polestar report convention:
- Polestar logo/header treatment
- clear title
- report type
- region
- reporting period
- polestar-advisory.com
- same header/footer logic as the other reports

Current country cover is close, but make sure it uses the same spacing, font, colour and footer treatment as the Watch reports.

4. Natural prose standard

Apply the same prose standard as all other reports.

Country reports must read like short analyst country briefs, not generated dashboard text.

Remove wording such as:
- “Polestar holds X records...”
- “The main issue type is...”
- “The highest severity recorded is...”
- “The most affected area on file is...”
- “Reporting volume is stable...”
- “Detail sits...”
- “Mixed reporting”
- “Data quality issue”

Use natural analyst prose.

Example replacement style:

Bad:
“Polestar holds 3 records for Papua covering 18 May 2026 - 19 May 2026. The main issue type is Other operational incident with 3 records.”

Better:
“Papua reporting for the period was dominated by armed-group activity and security-force incidents, with Yahukimo and Intan Jaya carrying the clearest operational signal. The small record set limits confidence, but the incidents point to continued pressure around movement, field access and local security coordination.”

Country prose should focus on:
- operating environment
- geography
- incident pattern
- business relevance
- movement/access implications
- source confidence
- what changed since the last period
- what to watch next

5. Country report section structure

Use this structure as the default:

- Executive Summary
- Fast Facts
- Situation
- What Happened
- What Matters
- Implications for Business
- Map / Incident Location View
- Severity Distribution
- Incident Breakdown by Type
- Related Incidents
- Source Notes / Data Notes
- Disclaimer

Optional sections where useful:
- Trend Summary
- Watch Next
- Polestar View

6. Fast Facts cleanup

Fast Facts should not show weak or meaningless labels.

For Country Reports, use:
- Reporting Period
- Total Records
- Highest Severity
- Most Affected Area
- Latest Incident
- Main Issue Type

But apply these rules:
- Capitalise location names properly: “Jayapura”, not “jayapura”.
- Do not show “Mixed reporting” as the main issue type.
- Do not show “Data quality issue” inside the card unless this is specifically a data quality card.
- If issue types are too mixed to name, use “Multiple issue types” or omit the card.
- If there are too few records for a meaningful top issue, say “Limited sample” in a data note, not in the main card.

7. Map capability

Add a map section to the Country Report Builder.

Purpose:
The country report must be able to include a map where incidents or specific activity can be plotted.

Map requirements:
- Add a Map / Incident Location View section to country report preview and PDF export.
- Plot incidents with valid latitude and longitude.
- Use severity-based markers using the Polestar severity colours.
- Include a simple legend.
- Include clear marker labels/tooltips in preview where possible.
- In the PDF, show a static map image or rendered map snapshot.
- Records without coordinates should not be plotted, but should remain in tables and totals.
- Add a data note: “Records without coordinates are included in totals and tables but not plotted on the map.”

Map should support:
- incident points
- specific activity points
- client locations or places of interest where provided
- routes or corridors later if already supported, but do not overbuild this now

Do not count flag state, source location or article publisher location as incident location.

8. Map styling

Use a clean, professional basemap.
Prefer Positron-style mapping where available.

Avoid:
- cluttered satellite view as default
- bright consumer-map styling
- oversized pins
- heat blobs that tell nothing
- unclear legends

Markers should be:
- small but readable
- severity coloured
- slightly translucent if overlapping
- bordered for readability

Use existing severity colours:
- Extreme: #800000
- High: #C0392B
- Moderate: #E67E22
- Low: #6FB872
- Insignificant: #B8C2CC

9. Charts and tables

Country report charts should use the improved Polestar chart style:
- restrained bars
- slightly softened/translucent fill
- subtle darker edge/stroke
- faint gridlines
- no gradients
- no shadows
- no decorative clutter

Tables should match the Watch reports:
- same header style
- same severity badges
- same fonts
- same row spacing
- clean wrapping
- no cramped labels

10. Data quality

Country reports must handle weak data clearly.

Rules:
- Do not invent precision.
- If the record set is small, say so plainly.
- If source coverage is weak, say so plainly.
- Records without coordinates stay in totals and tables but not maps.
- Records without a clear incident location should not be used for area charts.
- Location names must be normalised and properly capitalised.

Example:
“Source coverage remains uneven. Records without reliable coordinates are included in the table and totals but excluded from the map.”

11. Keep country reports separate

Country reports are not part of the standard Reports page.

Do not add them to the main Reports page unless explicitly requested.

They should remain in the Country Report Builder / country profile workflow, but use the same shared report design system.

12. Acceptance check

Using the Papua country report:
- Roboto is used in preview and exported PDF.
- Approved Polestar colours only.
- Cover aligns with Watch report convention.
- Prose no longer starts with “Polestar holds...”
- “jayapura” is corrected to “Jayapura”.
- “Mixed reporting / Data quality issue” does not appear as a weak Fast Facts card.
- A map section appears if incidents have coordinates.
- Incidents with coordinates are plotted.
- Incidents without coordinates remain in totals and tables but are not plotted.
- Severity distribution uses the same chart style as the other reports.
- Related Incidents table matches the wider report style.
- Country report feels like the same Polestar product suite, while remaining outside the Reports page.
