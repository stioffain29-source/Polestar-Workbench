# Energy / fuel / fertiliser world-scope monitors

Energy, fuel, and fertiliser are GLOBAL commodity markets, so their monitors
attribute and map incidents ANYWHERE, not just the APAC + Middle-East region.
Every other topic stays region-locked. This was an explicit owner decision:
**1a = world map** (out-of-region incidents shade the map AND appear in the
country table, with STRICT map == table parity — real countries only, NO blocs)
and **2b = surface only what the existing feeds already caught (NO new feeds).**

**Why:** the feeds always pulled global stories; the region gate was silently
dropping them. The fix is to widen attribution + map framing, not add sources.

## The moving parts (all must stay in lockstep)

- **Gazetteer** (`lib/ingest/src/topicConfigs.ts`): `GLOBAL_TOPIC_ALIASES = [...COUNTRY_ALIASES, ...GLOBAL_EXTRA_ALIASES]`.
  `GLOBAL_EXTRA_ALIASES` = the out-of-region canonicals (large land masses only),
  each with a centroid. Wired to energy/fuel/fertiliser configs ONLY. Exported
  from the `@workspace/ingest` barrel.
- **Relevance**: the energy geography-excludes were DROPPED (quality/homonym
  excludes kept) and `RELEVANCE_RULE_VERSION` bumped so the boot backfill
  re-cleans persisted rows.
- **Historical re-home**: `lib/ingest/src/globalReattribute.ts`
  (`runGlobalCountryReattribution`) is a marker-gated one-time migration
  (`global_country_reattribution_v1`) that runs BEFORE `backfillRelevance` to
  re-attribute old Unknown/mis-filed rows to their now-known country.
- **World choropleth polygons**: `artifacts/workbench/src/assets/worldChoroplethExtras.geo.json`,
  generated by `scripts/src/gen-world-choropleth-extras.ts`
  (`pnpm --filter @workspace/scripts run gen:world-choropleth`) from Natural
  Earth 110m (`world-atlas`). It holds ONLY the `GLOBAL_EXTRA_ALIASES` countries
  (16), which are all absent from the region assets, so nothing double-draws.
- **Map**: `CountryChoroplethMap` takes `scope?: "region" | "world"` (default
  region). World scope shades the union `cargoScope ∪ monitorExtras ∪ worldExtras`
  and reframes to `center [20,10] zoom 2`. `Topic.tsx` sets `worldScope` for the
  three topics; **fuel is NOT choropleth** (`useChoropleth` = energy||fertiliser)
  so fuel's CircleMarker point map got the same world framing separately.
- **Guard test**: `__tests__/workbench/worldChoropleth.test.ts` asserts every
  `GLOBAL_TOPIC_ALIASES` canonical has a polygon in the world union (with the
  inline `{UAE}` alias mirroring `CHOROPLETH_COUNTRY_ALIASES`), and that
  worldExtras is exactly the out-of-region set with no dups/overlap.

## Stored-row foreign-syndication mis-stamps (all three topics)

The `runGlobalCountryReattribution` pass (marker `global_country_reattribution_v1`)
only ever moves a row Unknown→anything or in-region→OUT-of-region; it deliberately
NEVER fires on in-region→in-region. So an Australia/India story blind-stamped with
another in-region feed default (e.g. an Australian fuel-crisis story tagged
Myanmar, a Kerala petrol story tagged Philippines) is NOT repaired by it. Fix those
with a marker-gated one-time relocate in `migrations.ts` that matches a target
country token in the TITLE only and requires NO OTHER tracked country token in the
title (title names exactly one country → relocate to it). Precedent markers:
`energy_foreign_syndication_relocate_v2` (energy: Turkey/UK/Venezuela) and
`fuel_fertiliser_foreign_syndication_relocate_v1` (fuel/fertiliser: France, Poland,
Australia, UK, Ukraine/Crimea, India). The title-only + others-guard also cleans
spurious multi-country co-tags (e.g. "India; Iran" on a pure Delhi petrol-price
story → India) since `country <> target` is exact-string. Added France + Poland to
`GLOBAL_EXTRA_ALIASES` + `COUNTRY_CENTROIDS` + city coords (paris/warsaw) + regen
choropleth. Left Taiwan OUT despite Unknown Taiwan fuel rows: its only signal is the
"Taipei Times"/"Focus Taiwan" masthead (masthead-pollution trap).

## How to apply / gotchas

- Adding an out-of-region country needs BOTH a `GLOBAL_EXTRA_ALIASES` entry WITH
  a centroid AND a re-run of the generator. The guard test fails if you add the
  canonical without regenerating the polygon.
- Do NOT regenerate the whole 177-country world into the asset: small-country
  gaps + map clutter. Reuse the region assets and add only the extras.
- Keep `CHOROPLETH_COUNTRY_ALIASES` as `{UAE}` only — it is the existing
  DB-spelling→polygon-name bridge, not a place to fix world scope.
- Region topics (flashpoint, conflict, cargo, shipping, protests, …) must stay
  byte-identical: they never pass `scope`, so they default to region.
- **Antimeridian band (Russia).** Natural Earth 110m stores Russia UNSPLIT across
  the antimeridian — one ring holds points near +180 AND near −180. When that
  country is SHADED (the energy/fertiliser world choropleth paints Russia),
  Leaflet draws the ring as a full-width horizontal BAND across the whole map.
  The generator's `unwrapAntimeridian` fixes it: any ring that genuinely crosses
  (a point >170 AND a point <−170) has its western-hemisphere (<0) points shifted
  +360 (Chukotka −170 → +190) so the ring stays contiguous just east of +180 and
  never spans the map; ordinary western-hemisphere countries (Canada/US/Cuba) are
  untouched because no ring of theirs crosses. **Why fertiliser looked clean but
  energy didn't:** SAME asset — the band only appears on whichever country is
  actually shaded, and the two maps shade a different value set. After ANY regen,
  verify no ring has both a point >170 and a point <−170 (Russia lon range should
  read ~20..191, never a full −180..180 span).
