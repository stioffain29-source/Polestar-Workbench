---
name: Flashpoint prose contradiction-killers
description: Rules for the Flashpoint WRITING layer (exec summary, forecast read, watch next) so the auto-prose never contradicts the charts/tables or oversells severity.
---

The Flashpoint prose builders live in `flashpointReportDataset.ts` (`buildAutoExecutiveSummary`, `buildForecastRead`, `buildWatchNextFromSignals`) and are mirrored into the PDF (`exportFlashpointReportPdf.ts`) and preview (`FlashpointReportPreview.tsx`). A client QA called the prose "not acceptable" for three contradiction/oversell classes; the durable rules:

**Forecast TABLE lead ≠ country CHART lead is NOT a bug — reconcile it, don't hide it.** The forward-looking table is ranked by confirmed FUTURE-DATED signals; the Records-by-Country chart is ranked by VOLUME. So the table can lead with country X (the only dated item) while the chart leads with country Y (most records). To a client this reads as a contradiction ("why does the forecast highlight Bangladesh when the chart leads with Philippines?"). The fix is an explicit reconciliation sentence: the table is a *scheduling signal* for the next cycle, not a ranking — plan for broad disruption in the volume leader and action the table country as a dated calendar item. `buildForecastRead` must receive the table's lead country/signal (`forecastFuture[0]`), not just a `hasFutureTable` boolean, to write this.
**Why:** the two surfaces answer different questions; suppressing one to "fix" the contradiction loses real information.

**Never name a "severity lead" / "sharpest escalation" unless genuinely elevated (SEV_RANK ≥ 3, i.e. Moderate+).** A `highestSeverity`/`topSeverityIncident` that is still *Low* is not an escalation. The earlier exec summary said "the sharpest single escalation sits in Bangladesh … rated Low" — self-contradicting. Gate every severity-divergence clause (exec summary, forecast read, watch-next severity bullet) on `>= 3`; below that, just report the ceiling ("severity topping out at Low") without dressing it as a divergence. Also: only tie a severity lead to the forecast table ("which is why it leads the table") when `hasFutureTable && forecastLeadCountry === sevCountry`, else the table claim is false.
**Why:** "highest" is relative; the reader hears "escalation" and the rating contradicts it.

**Watch Next must ALWAYS top up to ~5-6 bullets.** The future-signal path used to `return` only the future bullets — with one future item the section was a single weak line. Lead with future signals, then ALWAYS append cycle-specific (volume lead, elevated severity lead) + standing operational bullets, dedupe on the leading clause, cap at 6.

**pickProse parity is a hard rule — define it ONCE and use it for EVERY section including Executive Summary, in BOTH preview and PDF.** The drift bug: the PDF rendered Exec Summary with a bespoke inline rule (`execRaw && !isGenericFlashpointProse ? execRaw : auto`) that did NOT append auto-prose for short (<240) non-generic editor text, while the preview used `pickProse` (which DOES append). Same report → different exec summary on screen vs PDF. Fix: one `pickProse` helper defined before the first section, used uniformly. `isGenericFlashpointProse` (render-side generic-seed replacement) is the mechanism that lets saved/prod reports drop boilerplate WITHOUT a reseed (prod DB is read-only). `forecastRead` has no editor override so it always lands fresh on prod.
**How to apply:** any new analyst section must go through the shared `pickProse`; never branch exec/forecast logic in only one of preview/PDF.

## Plain-English prose standard (Aug 2026, owner-mandated)
- All flashpoint auto-prose builders rewritten to plain English: no analyst-speak. Banned phrases live in exported `FLASHPOINT_BANNED_PROSE_RE` (flashpointReportDataset.ts) and are enforced by `validateFlashpointReportDataset` check 4 (banned phrasing, quoted-headline paste ≥25ch, cross-section paragraph duplication). Same rules mirrored as instructions in the api-server AI prompt (reportProse.ts, REPORT_PROSE_PROMPT_VERSION v2). Keep the two lists aligned.
- Never quote/paste headlines into sentences — use `shortSignalLabel` (which now has prison-riot and riot rules so the raw-title fallback rarely fires).
- Contained incidents (prison/jail unrest) get an explicit "inside a prison, not wider disorder" hedge via `containedVenueNote`, gated on in-facility cues ("prison riot", "inmates clash") and vetoed by "outside/near the jail" (street protest at a prison gate is NOT contained).
- Polestar View must state risk level + where disruption is likely + concrete actions, never just a verdict.
- Same-event fold: response-angle vocab (troops/deploy/contain/security…) added to SAME_EVENT_GENERIC, plus a facility-class fold — same explicit country + 3d window + both titles anchored on prison/jail + no distinct subjects ⇒ one event (owner: "the same incident cannot be two different ratings"). Distinct named prisons still stay apart via the distinct-subject guard.
- PDF `pickProse` now mirrors preview exactly (incl. `isGenericFlashpointProse` suppression) — keep them identical.
