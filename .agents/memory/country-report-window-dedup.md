---
name: Country report window dedup layer
description: Where syndication dedup must happen for country reports, and why the generic vs PNG layouts can silently diverge.
---

The generic country report renders its active 7-day window WITHOUT deduping syndicated copies unless you dedup at the `windowIncidents` input to `computeCountryFastFacts`. That single input is the choke point: `computeCountryFastFacts` derives every window surface (severity/type/area counts, latest date) from it AND returns it unchanged as `facts.windowIncidents`, which the Related Incidents table, the map and the charts all read. Dedup there and all of them agree; dedup only the table and the counts/map drift.

**Why:** the PNG country layout dedups internally (`buildPngReportDataset` → its own `dedupeByTitle`), but the GENERIC layout had no dedup, so the same wire re-run under an identical headline showed and counted twice (e.g. Papua showed one VOI.id incident on two dates). The two report variants dedup at DIFFERENT layers, so a fix on one does not cover the other.

**How to apply:** for the generic path, run `dedupeCountryWindowIncidents` (in `monitorDedupe.ts`, keys on `canonicalTitleKey`, keeps best by severity then newest `occurredAt`) over `active.incidents` and feed the result to BOTH `computeCountryFastFacts` and the prose drafter. Leave the PNG `buildPngReportDataset` call on raw `active.incidents` (it dedups itself). Also note `cleanIncidentTitle` only strips keyword-list mastheads — a bare-domain publisher handle ("voi.id") needs an explicit bare-domain branch to be stripped from display.

**Two dedup authorities, one caption (structured/operating-risk path):** the structured country dataset has a WEAK dedup (`dedupeByTitle` over `windowItems`) and a STRONG same-story authority (`consolidateCountryStories` in `countrySameStory.ts`) used for the severity chart + fast facts. Any chart whose caption claims "deduplicated incidents" must count over the STRONG authority, not `windowItems` — the structured TYPE chart silently used the weak pass and over-counted near-duplicate / named-premises stories until wrapped in `consolidateCountryStories`. Consolidate ONLY the chart's counting; the Top-3 value scoring needs cluster sizes, so do not collapse `windowItems` globally. **Why:** a "deduplicated" caption on an un-consolidated chart is a fabrication-adjacent lie and disagrees with the severity chart sitting beside it.

**Map precision reads raw `location`, never the province bucket:** Reporting Confidence (§16) plottability and the map's precise markers must both classify the RAW incident `location` string (`classify/summariseLocationConfidence({location: i.location})`). A province/centroid bucket is NOT a plottable point — feeding it to the confidence gate fakes High precision. `PngReportItem` carries `location` (default-safe null) so the dataset-layer §16 gate sees the same signal the map does.

**PATH 4 armed-clash syndication (`clusterSameStoryRows`, `countrySameStory.ts`):** cordon-and-search / gunfight stories syndicate under wildly different headlines ("Gunfight rages in Shopian" vs "Army, J&K Police And CRPF Surround Two LeT Terrorists In Shopian") so Jaccard falls below the floor and PATH1–3 miss them, re-listing ONE event as many rows. PATH4 merges only when BOTH headlines report an armed clash (`ARMED_CLASH_RE`) AND share a DISTINCTIVE PLACE token, within a TIGHT 2-day window and a small Jaccard floor (≥0.1). **Critical:** the place anchor deliberately EXCLUDES generic clash/security words and broad-geography tokens (`CLASH_GENERIC_TOKENS`: south/kashmir/jammu/compass directions/terrain) so two DIFFERENT towns in the same region never merge on the region name, and the same town >2 days apart stays separate. **Why:** a false merge hides a real distinct incident (worse than a missed merge under no-fabrication); the town + tight window + clash-on-both are what make it safe. Verify with the 4-row Shopian set (must collapse to 1) plus negative controls (distinct town / same town 4 days apart → stay split).
