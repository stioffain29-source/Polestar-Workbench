---
name: Flashpoint weak-operational filters
description: Classes of records the classifier accepts on surface keywords but which must be filtered out of Flashpoint prose / tables / Related Incidents.
---

The Flashpoint topic classifier is intentionally permissive on surface vocabulary (protest, strike, rally, curfew) because it is the single gate into the entire report. The downstream prose builders and Related Incidents must apply a second, stricter filter for *operational* signal. The recurring noise classes are:

- Stock-photo wire captions ("Licensable picture: ... — Reuters Connect", Getty / Alamy / EPA-EFE).
- Sports-media protests (French Open prize money, ATP, NBA, etc.). Players-vs-league disputes are not public-order risk.
- Strikes / rallies that have been *suspended, called off, cancelled, withdrawn, postponed* — the live signal is gone.
- Retrospective legal process about a past public-order event (SK martial-law trials, perjury sentencings, "ex-spy chief denies allegations", anniversary commentary). Civil unrest must mean *live* public-order risk.
- Standalone court verdicts (suspended terms, indictments) that the classifier keeps because of "rioters" / "courthouse" vocabulary but which carry no live disruption.
- SEO keyword-stuffed captions: 3+ commas in title, or non-Latin script mixed with English keyword runs in the same title — almost never real headlines.
- Non-APAC headlines syndicated by an APAC outlet. Strip the trailing " - <Source>" suffix before testing geography; the source name is often the only APAC token.
- Defence-procurement / weapons-system wire copy ("India offers BrahMos", arms/defence deals, fighter-jet/submarine acquisitions) — kept by the classifier on the word "strike" ("precision strike", "strike range") but it is not public-order risk.
- Legislative / parliamentary process ("X passes bill", "cabinet clears law", "co-payment bill") — wire copy often says "opposition protests" rhetorically so it files as Protest, but it is not a street event.
- Sports keyword noise ("striker", a "11-second strike", tennis "rally", title "march") beyond the named-league filter. Motorsport is a sneaky case: "rally" is also a protest synonym, so a WRC headline ("Paddon's final Rally1 event - DirtFish") passes the protest gate. Catch it on motorsport-specific markers (rally1/rally2, WRC, DirtFish, Autosport, Motorsport, MotoGP, Grand Prix, F1/Formula 1, "special stage"/SSn), NOT the bare word "rally".

**"rally"/"strike" are the single worst noise source — keyword filtering alone is never "done." Verify with a live KEPT-vs-DROPPED audit, not a self-checking harness: `pnpm --filter @workspace/workbench run audit:flashpoint` dumps both lists straight from `/api/incidents` so a human can eyeball them. The first homonym pass still leaked ~9/34; these are the senses that survive a naive "needs an instrument/league word" filter:**
- Market rallies signalled by a RESULT word, not a named instrument: rout / valuation / profit / "N% rally" / "AI infrastructure rally" / "tin rally lifts profit".
- Sports match-report vocab the league list misses: a goal "strike" at half/full-time, "players rally" behind a team-mate, "protest the referee's call", regional sports (sepak takraw, kabaddi, etc.).
- Business "strike a deal" (commercial agreement, not industrial action).
- Fact-check / debunk pieces that say it is NOT a protest.
- Opinion-poll / approval-rating stories (a survey result, not an event).
- Public-health outbreaks (bird flu / dengue / etc.).
- Non-APAC protests syndicated by an APAC outlet ("...EU on Georgia's independence day - Free Malaysia Today").

**Where each belongs (layer matters):** topic-irrelevance homonyms (market/sports/deal/fact-check/poll/health) go in `FLASHPOINT_EXCLUDE` (`topicRelevance.ts`) — a hard exclusion that runs before the relevance tiers, so it cleans the report dataset AND the generic seeding path at once. Geography drops stay in `NON_APAC_FOCUS_RE` (`flashpointReportDataset.ts`), which strips the trailing " - <Source>" suffix first.

**EXCLUDE-precedence trap (bare-token danger):** in `topicRelevance.ts`, EXCLUDE patterns run BEFORE REQUIRED and always win — so a bare ambiguous token in an EXCLUDE list silently hard-drops legitimate records that no REQUIRED cue can rescue. Never put a bare token like `/\bfbi\b/`, `/\bogun\b/`, or `/\bnewbuild\b/` in EXCLUDE: an FBI-assisted APAC hijack, an APAC record that merely contains "ogun", or an attack on a newly-built tanker would all vanish. Gate every EXCLUDE token on disqualifying *context* — FBI on advisory/warning framing (incl. CJK 경고/警告), Ogun on Nigeria/police, newbuild on orderbook/sale/finance verbs. **Why:** EXCLUDE has no second chance; a false-positive exclude is invisible (the record never appears) so it is far more dangerous than a missed include. **How to apply:** when adding any cargo/shipping/fuel EXCLUDE, ask "could this single word appear inside a genuine operational APAC incident?" — if yes, pair it with the noise context, and re-run `scripts/auditReports.ts` to confirm the included count moves only by the intended records.
**Two anti-over-match rules learned the hard way:** (1) broad lexical tokens like "full-time" are unsafe at the hard-exclusion layer ("full-time workers rally" is real) — anchor them to an adjacent sports word. (2) Do NOT geo-drop on `ukraine`/`russia`: APAC solidarity protests are real public-order events; keep `georgia` only, and keep `APAC_HOOK_RE` stocked with major APAC *cities* (Tokyo, Seoul, Manila…) so a city-named solidarity headline survives even when it names a non-APAC cause.
**Consciously-kept borderline records (do NOT keyword-filter — the cure is worse):** awareness stunts whose *cause* is non-APAC but which are real public-order events were the original worry, but "Kite of Dreams … amplify voices of Gaza Children" is a stunt, not a street event, and is now dropped via the novelty/awareness-stunt class. The Icelandic "Eimskip" labour strike mislabelled Philippines is now ALSO dropped (foreign-maritime entity mislabel) — the prior "needs entity resolution, leave it" stance was reversed because the FOREIGN_ENTITY / Eimskip cue is specific enough not to catch genuine APAC strikes. Still do NOT geo-drop on bare "Gaza": a real pro-Palestine APAC protest must survive.

All three new classes are gated on `!LIVE_PUBLIC_ORDER_RE`: a *genuine* protest against a bill or arms deal will mention a crowd/march/tear gas/road closure and is kept; rhetorical "opposition protests the bill" copy is not. Do NOT broaden the exemption to the bare word "protest" — that re-admits exactly the junk (e.g. the "Japan passes bill" item) the user flagged.

**Why:** the classifier sees the report as a corpus; the reader sees one record at a time. A "protest" record with no place, no actor, no impact and no time-of-day is worse than no record. It signals to the reader that the brief is keyword-driven, not analyst-driven.

**How to apply:** keep weak-operational filtering at the dataset layer (between classifier and prose builders), never in the classifier itself — the classifier must keep these records visible in raw counts so reporting is honest. Apply identically to activism rows, unrest rows, Watch Next / forecast extraction, and Related Incidents prioritisation; any one of those leaking weak items will rebreak the brief.

Civil-unrest live-hook gate: a record is allowed only if it contains a current public-order verb (crackdown, tear gas, water cannon, baton, curfew imposed / extended, road closure, roadblock, clash, mass arrest, sit-in, troops deployed). The presence of "curfew" or "martial law" alone in a legal-process headline is not enough.

Related Incidents diversification: rank globally, then do a country-round-robin first pass (one record per country until cap), then fill remaining slots from the global ranking. Otherwise the strongest single country (PTI / Pakistan in this corpus) eats every slot.

Forecast signal labels must never fall back to a bare "Protest mobilisation". Compose them as `actor + trigger + form` and append `(City)` when a city is detectable in title/summary. The country column already carries the country.

Forecast table must also dedupe by `(country, signalLabel)` after shortSignalLabel is applied. Title-level dedupe alone is not enough: two distinct records (e.g. a Samsung pay-talks strike notice and a court injunction against the same union) can both collapse to "Union injunction ruling — sectoral strike risk" for South Korea and render twice. Collapse on the rendered label, not just the source title.

Out-of-scope crime classifications (Armed robbery, Armed group activity, Crime / public safety, Piracy / armed robbery) must be hard-dropped at the dataset root — *before* enriched/countryCount/highestSeverity are computed — not only at the Related Incidents prioritiser. Filtering only at Related lets crime records skew the country chart, the highest-severity Fast Fact and the auto Executive Summary's "shaped by" driver line; the reader then sees an exec summary that talks about robbery in an activism brief.

**Single-selector rule (the contradiction killer):** Flashpoint/Protests had THREE divergent filter regimes that disagreed — (A) Fast Facts + Related Incidents counted from an `enriched` set that *kept* weak/novelty items "so totals stay honest"; (B) prose reads used the cleaned activism/unrest rows; (C) the form-seeded prose used `filterIncidentsToWindow({byTopic:true})` which for a `protests` report only saw the `protests` bucket, never the merged `flashpoint` bucket — so it seeded "No usable signal" while Fast Facts showed records. Fix: ONE exported selector `selectFlashpointUsable(incidents, topic, issueDate)` returns the single clean set (merged flashpoint+protests, minus kinetic/court/crime/novelty/weak-operational, deduped); BOTH the dataset builder AND `draftTopicReportProse` (for flashpoint|protests) consume it. **Why:** the "honest totals" design was the bug — the count must equal the narrated/tabled set or the brief self-contradicts. **How to apply:** never reintroduce a separate "honest count" that includes records the prose/table exclude; if you add a consumer of flashpoint incidents, route it through `selectFlashpointUsable`, not a fresh filter.

**Feed-category source poisoning (the #1 silent gate-defeater):** Google-News-style feeds label every record with a parenthetical category in the `source` field, e.g. `"Google News — Japan (Civil Unrest)"`. `haystack()` in `topicRelevance.ts` concatenates `source` into the searched text, so that `(Civil Unrest)` injected the topic phrase "civil unrest" into EVERY flashpoint record — satisfying the unambiguous public-order tier for free and making the ambiguous-token gate a no-op (a motorsport "Taklimakan Rally" or "ArenaPlus NBA strike sports betting" sailed straight in). Fix: strip the parenthetical from `source` before building the haystack (`(i.source??"").replace(/\([^)]*\)/g," ")`). Relevance-kept dropped 624→335. **Why:** the feed's own taxonomy is not evidence the *record* is on-topic; treating the category label as body text defeats every keyword gate. **How to apply:** never let a feed-supplied category/section label into the relevance haystack — strip parentheticals (and any "(Category)" suffix) from `source` first; verify with the live audit, not the self-checking classifier harness (the harness only catches it once you add a `source:"...(Civil Unrest)"` regression case).

**Diplomatic homonyms (operational gate, `flashpointReportDataset.ts`):** two senses collide with street protest. (1) A STATE "lodges/files/registers/raises a protest with an embassy / high commission / ambassador" (also note verbale, démarche, summon the ambassador) — a diplomatic act, not public order. (2) Head-of-state travel framing ("junta chief … heads to India, with an eye on China") that mentions a protest only as historical background. Both are dropped via `DIPLOMATIC_PROTEST_RE` / `DIPLOMATIC_VISIT_RE` gated on `!LIVE_PUBLIC_ORDER_RE`. **Critical narrowing:** the protest-verb branch MUST require an explicit diplomatic OBJECT within ~60 chars (lookahead for embassy/high commission/ambassador/envoy/consulate/chargé/foreign ministry/note verbale/démarche) — a bare "students raise a protest over fees" or "workers file a protest against layoffs" is a REAL street action and must be KEPT. Likewise bind "with an eye on <power>" to a preceding head-of-state subject + travel verb; never leave it as a standalone branch (it would drop any real protest that merely names a great power). **Why:** these verb stems (lodge/file/register/raise) are common to both diplomatic and street protest; only the object disambiguates. **How to apply:** when adding a homonym filter at the operational layer, anchor it on the disambiguating *object/context*, not the shared verb, and confirm via audit that the real-protest count doesn't drop.

**State démarche WITHOUT an embassy object (`LODGE_DIPLOMATIC_PROTEST_RE`):** some diplomatic protests name no embassy at all — "Malaysia lodges strong protest after Israeli interception of Gaza flotilla" — so the object-gated `DIPLOMATIC_PROTEST_RE` misses them. The safe disambiguator here is the diplomatic REGISTER: scope to the verbs lodge/convey AND REQUIRE a register adjective (strong|formal|official|diplomatic|stern|firm|strongly-worded) before "protest", still gated on `!LIVE_PUBLIC_ORDER_RE`. **Why:** keying on the verb form alone (`lodg…protest`) over-drops genuine domestic mobilisation ("residents lodged a protest at the collectorate", "workers lodged a protest demanding wages") which carries NO register adjective; the adjective is what marks a state démarche. Verified across windows: Malaysia's démarche drops on 2026-05-24 while genuine Malaysia items are KEPT on 2026-05-17 and 2026-05-31. **How to apply:** never widen this to bare lodge/convey + protest, and leave file/register/raise to the object-gated regex above.

**`\bprotest\b` never matches the plural (the silent under-selection bug):** in `topicRelevance.ts` REQUIRED patterns, `\bprotest\b` failed on "protests"/"demonstrations" because there is no word boundary before the "s". This blocked whole countries from the weekly report. Fix: suffix the stem with `(e?s|ers?|ing|ed)?`. **Why:** weekly Flashpoint must show the FULL regional (APAC) picture — every in-scope country with genuine unrest, no fixed country cap; a missing boundary quietly suppressed real records. **How to apply:** prove coverage by running `scripts/proveFlashpointSelection.ts <issue-date>` across SEVERAL windows (it prints included-by-country + rejected-with-reason from the live `selectFlashpointUsable` over merged flashpoint+protests) — a healthy week shows up to ~12 countries, not 5.

**Prose record-count denominators must use `enriched.length`, not the activism+unrest split:** `buildForecastRead` computed `total = activismRows.length + unrestRows.length`, which omits records bucketed as neither, so its "X of Y records" read one short ("8 of 17") while the executive summary used `enriched.length` ("8 of 18"). Pass `fileTotal: enriched.length` and use it for the headline counts only (keep `total` for activism/unrest share math). **Why:** two different denominators in the same brief make it self-contradict. **How to apply:** any "of N records" prose must derive N from the single selected set, not a per-bucket subtotal.

**Proof harness = real pipeline over merged buckets:** `auditLiveRelevance.ts` must run the actual `selectFlashpointUsable(merged flashpoint+protests, "flashpoint", issueDate)` — a `protests`-topic report maps to data topic `flashpoint` and merges BOTH buckets, so auditing the `protests` bucket alone yields a misleading FINAL=0. Print relevance-kept → FINAL REPORT SET → second-stage drops so a human sees included + rejected-with-reason. The architect's standing caveat: conservative false-drops (e.g. a real but comma-spammy "Cab, auto strike in Delhi-NCR" lost to the SEO-caption heuristic) are ACCEPTABLE per the user's "signal thin > noise in" preference; do not loosen the spam/ambiguous gates to rescue them, as that re-admits the flagged noise.

**Title-rescue must NOT run before the homonym exclude (the bypass bug):** in `topicRelevance.ts` the flashpoint branch has a title-rescue that returns `relevant:true` the moment the headline contains an unmistakable public-order word ("protest"/"demonstration"…). It was placed BEFORE `FLASHPOINT_EXCLUDE`, so any sports/finance/photo-gallery headline that merely contained the word "protest" was rescued before the homonym filter could drop it — e.g. "Malaysia awarded takraw title after Thailand **protest** referee's call" and "**Protest** held vs tree cutting | Photos | GMA". The takraw/referee homonyms already existed in `FLASHPOINT_EXCLUDE`; they were just never reached. Fix: a dedicated `FLASHPOINT_TITLE_HARD_EXCLUDE` subset runs against the TITLE before the rescue. **Critical:** the title pre-check must contain ONLY homonyms that can never appear in a genuine protest headline (sports-result: takraw/referee's call/"rally past"/named teams; photo-gallery `| Photos |`/`(Photos)`; betting; fact-check "not a protest"). It must NOT apply the full `FLASHPOINT_EXCLUDE`, because the ambiguous classes (military "air strike", weather "cyclone strikes", finance "extend rally") legitimately co-occur with the word "protest" in real headlines — anti-war and disaster-response protests — and those must stay body-only so the rescue still saves them. **Why:** rescue and exclude both look at the title; whichever runs first wins. A hard *unambiguous*-noise homonym must beat the bare keyword, but an *ambiguous* token must not (the rescue exists precisely because real protest titles carry them). **How to apply:** any "decisive keep" shortcut (title-rescue/allowlist) ordered before excludes must front-run ONLY a curated unambiguous-noise subset, never the full exclude list. Verify with `scripts/proveFlashpointSelection.ts <issue-date>` (read the FULL included titles, not counts) AND a synthetic keep/drop harness covering anti-war + disaster protests.

**CJK / non-Latin EXCLUDE patterns (cargo & friends):** `haystack()` lowercases everything, so any Latin letters in a non-Latin pattern (e.g. Korean "LA서") must use the `/i` flag or be written lowercase — an uppercase `LA서` silently never matches. CJK homonym danger mirrors the bare-token trap: a bare `米` means BOTH "US" and "rice" (a real APAC cargo commodity), so never exclude on it — gate US-jurisdiction noise on unambiguous context (`司法省` = US DOJ, plus a response-strengthening-lobby frame 対応/対策 + 強化/要請). Verify every CJK exclude against the live audit, not by eye — a wrong flag or width looks plausible but matches nothing (or worse, too much).

**Slop excludes are reused OUTSIDE the text gate (`hitsSlopExclude`):** the flashpoint slop half — `FLASHPOINT_EXCLUDE` + the title-only `FLASHPOINT_TITLE_HARD_EXCLUDE` — is also exported via `hitsSlopExclude(topic, i)` and consumed by the GDELT lane-promote pass + a boot reclean to strip noise from lane-vouched incidents WITHOUT re-running REQUIRED. Consequence: any slop exclude you add here now also affects promoted rows, and the reclean must be re-triggered by a fresh marker-gated migration (the version backfill can't reach `gdelt_cloud:%`/`tapa_offline:%` rows). Keep the split clean — only NOISE belongs in the exclude lists; REQUIRED/keep logic must stay out of `hitsSlopExclude` or promoted rows lose their lane vouch. See `gdelt-structured-layer.md` and `conflict-relevance-excludes.md`.
