# Structured country report (Papua New Guinea + West Papua + Indonesia + Jakarta)

The structured 9-section security brief (location buckets + incident cards) is now CONFIG-DRIVEN and serves FOUR theatres: Papua New Guinea (`papua-new-guinea`), Indonesian West Papua (`papua`), Indonesia national (`indonesia`), and Jakarta city (`jakarta`). All other country slugs keep the generic country-report template.

## Indonesia + Jakarta were added with NO new feeds/ingest/AI/server-prose — config + gazetteers only
The two newest theatres are a pure FRONTEND extension: new gazetteers (`lib/ingest/src/indonesiaExtract.ts` national-province + `jakartaExtract.ts` district), two `StructuredTheatreConfig`s (`INDONESIA_REPORT_CONFIG` 6 regional buckets, `JAKARTA_REPORT_CONFIG` 5 districts + Greater Jakarta) + `build{Indonesia,Jakarta}ReportDataset` wrappers, the `structuredTheatre` gate widened to `png|westPapua|indonesia|jakarta`, and idempotent `country_reports` seed rows (`indonesia`/`jakarta`, region APAC) seeded in `migrations.ts` BEFORE the baseline loop (select-by-slug + onConflictDoNothing so analyst edits never clobber, rows recreate if deleted, reaches read-only prod on deploy boot). Indonesia/Jakarta `country_reports` rows have province/category columns NULL, so they render ENTIRELY through the `config.extractItem` derive fallback — `toItem(i,config)` gained an optional `config.extractItem` that fires only when the API column is null (PNG/WP columns populated → fallback inert → zero regression). **Gazetteer province/area display strings MUST byte-match the `bucket.provinces` lists in the config** or an item silently falls to "Other".
**Jakarta is country-scoped to Indonesia, not its own country** — there is no Jakarta row in the incident country field. The incidents memo Jakarta branch is `incidentMatchesCountry(i.country,"Indonesia") && isJakartaScoped(title,summary,location)`. The incidents query has NO country param; all theatre filtering is client-side.

## isJakartaScoped MUST be precision-first — "Jakarta" is metonymic for the central government
A bare "jakarta" token is NOT proof a record is a Jakarta-LOCAL event: Indonesian reporting routinely uses "Jakarta" to mean the national government, or as a meeting/source/context mention while the event is elsewhere (e.g. a Medan robbery whose victim is a "Jakarta logistics entrepreneur", a North-Sumatra blackout dateline "Jakarta"). The gate is three-tier: (1) a resolvable district / Greater-Jakarta gazetteer locality → IN; (2) the specific non-metonymic tokens `jabodetabek`/`dki jakarta`/`dki`/`greater jakarta` → IN; (3) a bare `jakarta` scopes IN ONLY when no competing non-Jakarta Indonesian locality (`INDONESIA_PROVINCE_BY_CITY` keys that ≠ "DKI Jakarta") also appears. Greater-Jakarta ring towns (Bekasi/Depok/Tangerang/Bogor) are caught by step 1 before the step-3 competing-locality scan, so they never self-exclude.
**Why:** the first cut treated any `jakarta`/`dki`/`greater jakarta` token anywhere (incl. summary) as citywide scope, which pulled out-of-town Indonesian stories into the Jakarta brief — a no-fabrication violation. The architect flagged it as blocking; a live replay over ~400 Indonesia rows confirmed the tightened gate keeps genuine Jakarta protests/PLN-palace items and drops the Medan/North-Sumatra "mentions Jakarta" stories.
**How to apply:** never loosen step 3 to a bare-token match; if a real Jakarta item is being dropped, add its district/landmark to the Jakarta gazetteer (step 1) rather than weakening the dominance guard.

## Adding/maintaining a structured theatre (the generalization)
`pngReportDataset.ts` holds a `StructuredTheatreConfig` (name, buckets→provinces, empty-location fallback, anchors); `PNG_REPORT_CONFIG` + `WEST_PAPUA_REPORT_CONFIG` drive a generic `buildStructuredReportDataset`. Public wrappers stay: `buildPngReportDataset` / `buildWestPapuaReportDataset`. `PngCountryReportBody` renders `dataset.buckets[]` generically (no hardcoded bucket keys) + an "Other …" catch-all. `CountryReport.tsx` routes via a `structuredTheatre` memo (`"png"|"westPapua"|null` from `acceptedCountryTokens`; `papua-new-guinea`→png, `papua`→westPapua); everything keys off `isStructured` NOT `isPng`. **Do NOT touch the local cross-border incident-filter memo** (its own isPng/isPapua at ~L198-219) — it stays separate from the structured gate.
**How to apply (a miss silently degrades that theatre):** new structured theatre = gazetteer + extract wrapper (`lib/ingest`) + backfill wrapper + dataset config + `structuredTheatre` gate + country-aware prose + SEED_SOURCES feeds + marker-gated boot backfill.

## Cross-border-safe enrichment (PNG vs West Papua must never overwrite each other)
One incident gets ONE theatre's province/category/business_impact/incident_date. PNG matches `country ILIKE '%papua new guinea%'`; West Papua matches `ILIKE '%papua%' AND NOT ILIKE '%papua new guinea%'`. The inline flashpoint ingest mirrors this; the WP backfill (`runWestPapuaExtractBackfill`) and the marker-gated boot block (`west_papua_structured_extract_backfill_v1`) use the exclusion, so a cross-border row keeps its single PNG enrichment rather than being clobbered by WP.
**Why:** without the `NOT ILIKE papua new guinea` guard the two passes fight over shared rows.

## Client-side extraction via the SHARED rulebook (the key architectural decision)
Per-item attributes (province / category / business-impact / occurred-vs-reported date) are derived **client-side** in the workbench. The duplicated copy was retired: `pngReportDataset.ts` now IMPORTS the one canonical rulebook from `@workspace/ingest/pngExtract` (subpath export; pure module — its only import is `./text` hasWord, no server deps), so there is a single source of truth shared by ingest + the report. Reason the derive still runs at all: the nullable DB columns (province/category/businessImpact/incidentDate) are NOT plumbed through the incidents API/OpenAPI/generated types, and prod is read-only from the workspace — columns stay null until republish + a fresh ingest WITH a backfill that does not yet exist (migrations only ADD columns; re-ingest only INSERTs new rows). Empirically EVERY PNG incidents-API row reads these four fields null in dev too, so the report is rendered entirely by the derive path today.
**How to apply:** the dataset keeps a prefer-API-else-derive fallback (`i.province ?? derived.province`, category+businessImpact as a pair, `i.incidentDate ?? derivePngIncidentDate`). Do NOT make it API-exclusive until a real backfill lands AND the columns are confirmed populated, or the whole report blanks. Any change to province keys or category rules now lands ONLY in `lib/ingest/src/pngExtract.ts` — no second copy to keep in sync. Workbench imports it as a pure lib (same pattern as @workspace/relevance / @workspace/strike-targets); do not add it to the workbench tsconfig references.

## In-app PDF parity is free; offline jsPDF parity is now an explicit branch
The in-app "Download PDF" rasterises the on-screen DOM (the project-wide pattern), so screen == in-app PDF automatically — the PNG body needs no separate PDF builder for the in-app button. The OFFLINE jsPDF path (`exportCountryReportPdf`, used only by headless scripts) now carries a structured-brief branch for ALL FOUR theatres: Jakarta has `renderJakartaBrief`; png/papua/indonesia share `renderStructuredBrief`, which mirrors `PngCountryReportBody`'s exact eight-section order (BLUF → Top 3 → Incident Details → Current Situation → Operational Impact → Recommended Actions → Outlook → Polestar View) then appends Situational Context + Disclaimer and returns early before the generic layout. The branch reuses the matching `build{Png,WestPapua,Indonesia}ReportDataset` (no duplicated prose) and recomputes themes/impact via `buildCountryIncidentThemes`/`buildOperationalImpactBullets` exactly as the component does. Theatre is picked with `acceptedCountryTokens(country.name)` (papua-new-guinea→png, papua→westPapua, indonesia→indonesia). Font safety: every new `pdf.text` is preceded by `setRoboto` and there are ZERO `setFont`/helvetica calls in the file, so the only used font stays /Roboto. NOTE: the headless `exportReportPdfHeadless.ts` script has no country-topic path, so an automated FONT_AUDIT for these is not wired — the guarantee is structural (no base-font call anywhere in the builder).

## Prose: ONLY Executive Summary + per-incident card summaries are AI-overlaid; EVERY other section (Outlook included) is deterministic
The PNG Executive Summary is LLM-generated, fingerprint-cached, and editable — reusing the SHARED country-prose table/route/hooks via a `variant` field (`"png"`), NOT a parallel table/route/migration. The server prompt+parser branch on `variant`; the `png` parser still fills executiveSummary+outlook (+ incidentSummaries, see below) and leaves the other 5 generic keys empty. **Outlook is NOT AI in the brief:** `pngEffectiveDataset` overlays ONLY `executiveSummary` onto the deterministic dataset, and the editor exposes ONLY Exec Summary + per-incident summaries — the tightened deterministic Outlook is the single rendered source. Do NOT re-add an outlook override; it would re-introduce non-determinism into a section the brief deliberately makes deterministic. `variant` is part of the fingerprint, so adding it invalidates every existing country cache once (self-healing regen). The other 7 PNG sections (Top 3, location buckets, Business Impact, Source Confidence) remain the deterministic builder, which is also the LABELLED fallback when AI is unavailable (the page-level "AI narrative unavailable" banner already shows screen-only). The AI prose is grounded on `pngDataset.windowItems` (the same deduped/attributed set the brief renders), mapped to the prose-incident shape — so the fingerprint hashes the rendered items. The template never emits parenthetical record counts (a hard user rule across all reports); a parenthetical LIST of watchlist locations is fine (it is not a count).
**Why:** lean reuse avoids a new DB table + boot migration + codegen; PNG slug is unique so no collision.
**How to apply:** the prose effect waits for `pngDataset` to build before firing (so the fingerprint is stable).

## Per-incident AI card summaries (the canned-template replacement)
Each incident card's body line is now a SPECIFIC AI analyst summary of THAT incident, grounded only on its own title+summary — replacing the canned per-category `businessImpact` template line. It rides the SAME `variant:"png"` prose object: `CountryProseSections.incidentSummaries` is an OPTIONAL `Record<incidentId,string>` (JSONB, no migration). The model returns summaries keyed by the 1-based incident NUMBER from the prompt; `parseSections` maps each number back to the incident id via `canonicalIncidents(incidents)` (so `parseSections` now takes the incidents arg) and stores an id-keyed map. `ProseIncidentInput.id` is therefore REQUIRED in the png path AND must be in `incidentIdentity()` (the fingerprint) — if an id changes the cached summary can no longer match its card, so the fingerprint must flip. `PngCountryReportBody` reads the map via a React Context (`IncidentSummaryContext`), so the shared `ItemCard` (Top 3 + every location bucket) renders `summaries[item.id] || item.businessImpact` with NO prop-drilling. `businessImpact` stays as the deterministic labelled fallback. Editing PNG now lists one editable field PER incident (keyed by `windowItems` id, labelled by title) under "Narrative (editable)" alongside the Exec Summary (NO Outlook field — Outlook is deterministic); the whole `proseDraft` (incl. incidentSummaries) persists on save for free. `PROSE_PROMPT_VERSION` bumped to invalidate the cache. `pngReportDataset` carries `summary` through so grounding text reaches both the prompt and fingerprint.
**Why:** the canned line repeated verbatim across same-category cards and said nothing about the actual event.

## ItemCard layout (clean left edge + chip aligned to title's first line)
The card header is an explicit inline flex (`alignItems:"flex-start"`, `justifyContent:"space-between"`): title `{flex:1,minWidth:0,textAlign:"left",lineHeight:"22px"}`, chip wrapper `{flexShrink:0}`. The fixed title `lineHeight` (px, not unitless) is what keeps the severity chip aligned to the title's FIRST line even when the title wraps to multiple lines. All body text blocks carry `textAlign:"left"` so nothing inherits centring.

## Syndication dedup
The page feeds the PNG builder the RAW window incidents (buildCountryLayers does not dedupe; only the lookback-prose set runs dropSyndicatedRehashes). So the builder must dedupe itself. Feeds carry the same story under headlines that differ only by a trailing " - Publisher" tail that cleanTitle leaves on when the tail doesn't match the row's own source (e.g. a Jubi.id story syndicated via a Google News feed). Dedup key therefore strips a trailing dash/pipe segment when the surviving prefix is still a substantial headline (≥5 words), then collapses to one representative (best by severity then recency).

## Cross-section dedup (Top 3 vs location buckets)
"Top 3 Incidents This Week" and the regional location buckets both derive from the SAME windowItems, so without an exclusion a top-3 incident is rendered twice (once in Top 3, again in its province bucket / "Other") — read as "duplication in reporting". The builder excludes the top-three ids from `bucketableItems` (feeds both config buckets AND otherNational); each incident is reported once. AGGREGATE sections (Executive Summary, Business Impact, Outlook, diagnostics) stay on the FULL windowItems — only the per-incident CARD lists get the exclusion.
**Why:** once-only reporting; a highlight section must not double-count.
**Edge case (do not regress):** a bucket whose only incidents were promoted to Top 3 is now items-empty, but rendering the empty-location fallback there would FALSELY claim no fresh reporting. So each bucket (and otherNational) carries `hadFeatured` (true when a windowItems∩top3 row belongs to it); the renderer shows `featuredAboveNote` (PNG_FEATURED_ABOVE_NOTE) instead of the empty fallback. With ≤3 total incidents every populated bucket goes featured-empty — provably truthful (hadFeatured true ⇒ featured note; truly-empty ⇒ fallback).

## Empty-location fallback (exact string, do not paraphrase)
"No fresh publicly reported protest, theft, robbery or major crime incident identified in open sources for this location during the reporting period."

## Deterministic analytical sections (BLUF / What Changed / Location Watchlist / Polestar View / Reporting Confidence)
These 5 sections are 100% deterministic in `buildStructuredReportDataset` — NO AI, NO new DB/server/editor/PDF-exporter. Render order in `PngCountryReportBody`: BLUF → Exec Summary → What Changed → Top 3 → buckets → Other → Location Watchlist → Business Impact → Outlook → Polestar View → Reporting Confidence. Both PNG + West Papua inherit (shared builder). Outlook is also tightened into most-likely / key locations / escalation triggers / what reduces concern. Business Impact left as-is.
**The week-on-week trend depends on a real prior baseline.** `BuildArgs.previousWindowIncidents?` is OPTIONAL; `resolvePreviousCountryWindow(layers, issueDate)` (in `countryReportLayers.ts`) supplies the 7d immediately before the current window, wired in `CountryReport.tsx`. The builder gates EVERY trend claim on `hasPreviousWindow = previousWindowIncidents !== undefined` — NOT on `previousWindowItems.length`. A quiet prior week (supplied empty array) is a VALID comparison; an absent field is NOT. When absent: `volumeTrend="nohistory"`, `trajectory="stable"` (BLUF reads "holds to the standing pattern", Polestar "continuity of the standing risk pattern"), and the What Changed lead drops the "Against the previous week," prefix (`capitaliseFirst(body)`) so it never says "Against the previous week, there is no comparable reporting from the previous week".
**Why:** an earlier bug let `prevWorstRank=0` (from an absent baseline) make `curWorstRank>prevWorstRank` true → every history-less report fabricated "deteriorating". Confidence rationale says "outlets report the picture" NOT "independent outlets corroborate" (we can't verify independence/corroboration from feed counts). Tier labels in prose stay Capitalised (no `.toLowerCase()` on severity labels). Empty current window → "no fresh open-source reporting", never "no risk".
**How to apply:** keep `hasPreviousWindow` as the sole trend gate; never infer a move from `length===0`. Location Watchlist renders as branded 3-col rows (Location | Why it matters | Recommended action), html2canvas-safe (content-box, no line-clamp).

## CATEGORY_RULES classify over title+summary, first-match-wins by rule ORDER
The structured extractor (`lib/ingest/src/structuredExtract.ts` `CATEGORY_RULES`) matches over title AND summary combined, and the FIRST rule in array order wins. So a civil-unrest verb sitting in the SUMMARY ("stormed", "clashed") will STEAL an armed-crime row unless an earlier crime rule (Armed robbery is above Civil unrest; Homicide is above it too) matches a crime noun first. Real defect: "Lae supermarket payroll robbery" whose summary read "Armed robbers stormed a supermarket…" classified as Civil unrest, because the rule had `armed robbery` (noun) not `armed robber(?:y|s)?` (the people) so civil-unrest's "stormed" won.
**Why:** owner's emphatic "you're not showing ANY criminal events" — genuine PNG crime (raskol robberies, cash-van/highway truck hijacks, sorcery-accusation killings/SARV/GBV) was being dumped into "Other security" (was the single largest PNG bucket at ~58/90d; dropped to ~18 once the crime vocab was completed, and Homicide+Armed-robbery now lead). The lead flips automatically because the brief's leads are volume-driven off the top categories — no prose edit needed.
**How to apply:** keep crime vocab COMPLETE and ordered ahead of Civil unrest. Homicide rule carries killing(s)/kills, rape/sexual+gender-based violence, sorcery-accusation-related violence/SARV/sanguma, `ambush(ed)`; Armed-robbery carries `armed robber(?:y|s)?`, `at gunpoint`, `cash-in-transit`/`cash van`, and transport-BOUND hijack (`(?:truck|lorry|vehicle|car|bus|pmv|…)[ -]hijack` — NEVER a bare "hijack" or a bare "gang", which false-hit metaphors / Bahasa "alley"). All crime tokens are English, so the shared Indonesia/Jakarta rulebook is inert. To re-classify PROD, bump BOTH backfill markers (`png_extract_backfill_*`, `west_papua_structured_extract_backfill_*`) in `migrations.ts` (a bump re-runs the onlyNull:false rewrite on deploy boot); re-classify DEV with `pnpm --filter @workspace/scripts run backfill:{png,west-papua}-extract -- --commit` (bypasses the marker). No RELEVANCE_RULE_VERSION bump — this is display categorisation, not the relevance gate.

## Development-wire display filter (why PNG leads read "vanilla")
The PNG brief's volume-driven leads (BLUF, Executive Summary, top categories/provinces, Top-3) read "vanilla" when LOW-severity development/PR wire copy (airport expansions, inaugural flights, "brings hope", scholarships) dominates the week's raw volume, burying the theatre's real crime/violence reality. Fix is a config-gated DISPLAY-side filter: `isDevelopmentWireItem(item)` applied to `windowItems` + `previousWindowItems`, gated by `StructuredTheatreConfig.filterDevelopmentWire` — set true on `PNG_REPORT_CONFIG` ONLY (West Papua/Indonesia/Jakarta inert). Empty-window fallback to the unfiltered set so the "no fresh reporting" strings only fire on a genuinely empty window. It NEVER touches the incident TABLE / Fast Facts (those stay on unfiltered `active.incidents`), so narrative composition can legitimately be smaller than the tile counts — counts stay honest by design. The dedup-strength signal reads a pre-filter `dedupedWindowItems` so it still measures syndication collapse only.
**Guardrails (strict under-filter bias — a veto only ever KEEPS, so no data loss):** general dev/PR wire drops only when Low (`severityRank < 3`) AND no security/hazard term appears anywhere (title or summary). A SEPARATE structural round-up-column marker (`HARD_NON_INCIDENT_TITLE_RE`, currently just `/\btidbits\b/`) drops a recurring newspaper miscellany column ("PC Online Tidbits", Post-Courier PNG) at ANY severity — a deliberate narrow deviation from the sev≥3 guardrail, justified because a round-up column carries no discrete event to lose. Its veto is TITLE-ONLY: a bare column title drops even though its grab-bag summary routinely mentions unrelated police/theft snippets (a summary-scoped veto made the marker permanently INERT on live data); a title that actually names an event (e.g. "Tidbits: gunmen raid store") stays. The true defect is upstream severity misclassification (the column is mis-rated Moderate); the title marker is the durable display hedge because the column recurs weekly.
**Why:** owner said the PNG brief reads bland vs its actual reality. Architect approved the config-gated display filter (approach C) + the narrow title-only structural marker. Verified on 138 live PNG rows: BLUF flipped from aviation-PR "deteriorating" to security-led "easing"; Top-3 #3 flipped from the "PC Online Tidbits" round-up to a genuine High sorcery/GBV item.
**How to apply:** keep the marker set to structural column/round-up NAMES only — do NOT grow it into a second general lexicon (use `DEVELOPMENT_WIRE_RE` for PR vocab, gated on Low). Never drop a genuine sev≥3 security item or any security-term item. Regression: `__tests__/workbench/pngDevelopmentWireFilter.test.ts`.

### The SECURITY_TERM_RE veto — not the Low-only gate — is the real safety net
PNG stored severity is unreliable (real crime is often mis-rated Low — see `pngSeverityCorrection.ts`), so the `severityRank<3` guard is weak; the security-term VETO is what actually prevents dropping a genuine event. That makes `DEVELOPMENT_WIRE_RE` safe to grow liberally, but it also means the veto MUST cover every hazard/crime class a Low-rated row could carry. Two gaps found + closed: (1) the veto lacked bare `fire|blaze|crash`, so a Low "Fire destroys classroom" (added token `classroom`) or "Plane skids off runway" could silently drop; (2) the veto was English-ONLY, but Bahasa `indonesia_local` rows demonstrably reach the PNG window (the Digicel 5G row proves it) — a bare Bahasa PR token like `jaringan`/`kembangkan` would drop a Bahasa crime headline ("Polisi bongkar jaringan narkoba"). Added Bahasa veto terms (kebakaran/penembakan/pembunuhan/perampokan/narkoba/penyelundupan/kekerasan/penyerangan/penculikan/polisi).
**Why:** owner fury that the PNG active week filled with development/PR slop (US-PNG "enduring relationship" ceremonies, barracks-classroom renovations, DASH-8 fleet farewell, 5G rollout, inflation, fashion runway, bursaries) while the real crime (tribal-violence massacre, Sepik piracy arrest, robbery, homemade-gun arrests, mining crackdown) sat buried. Extending the lexicon flipped Top-3 to lead with the Extreme massacre + the piracy arrest (live-DB proof: 56 country-kept → 34 after dev-wire).
**How to apply:** prefer REMOVING a collision-prone PR token when another token already covers the target row (dropped `runway` — fashion row still drops via `designer`/`new collection`; dropped bare `jaringan`/`kembangkan` — 5G row still drops via `\b5g\b`) rather than relying on the veto to paper over it. Any new PR token that could appear in a genuine event needs a matching veto term added in lockstep. No RELEVANCE_RULE_VERSION bump — display filter only.

## Top-3 lead ranking = value-select + LEAD-ONLY security guard (NOT a tier-dominant sort)
The Top-3 developments are SELECTED by analyst value (`compareClusterByValue`: scoreClusterValue then severity-then-recency) so the week's most significant DISTINCT events make the cut — incidental hazards included. A separate LEAD-ONLY guard in `selectTopStoryClusters` then promotes the best value-ranked SECURITY cluster to the #1 slot: `leadSecurityTier` = 0 for `NON_SECURITY_LEAD_CATEGORIES` (Explosive remnants of war / accidental explosion, Fire, Natural hazard, Environmental / haze), 1 otherwise; if `ordered[0]` is tier-0, splice the first tier-1 cluster to the front. It is a pure reorder — count-invariant, drops nothing.
**Why:** an accidental blast, however deadly, must never LEAD a security brief, but it must still be REPORTED prominently. The Biak WWII-ordnance blast (EXTREME, 9 dead) belongs at #2, NOT #1 and NOT dropped. An earlier tier-DOMINANT sort (applied at BOTH the pre-selection `storyClusters.sort` and the display sort) over-corrected: it pushed the EXTREME hazard clean out of Top-3, letting a LOW aviation item take slot #3 — the opposite failure. Result now: Yahukimo separatist clash (HIGH) leads, Biak (EXTREME, "Explosive remnants of war / accidental explosion") at #2, Intan Jaya (HIGH) #3.
**How to apply:** use ONE value comparator at both sort sites; enforce the security-lead rule ONLY on the #1 position, never as a whole-list sort key, or the deadly hazard vanishes from the brief. Known narrow limit (accepted): if all three value-top picks are hazards while the top security story sits at rank ≥4, a hazard still leads — the guard can only promote a SELECTED cluster.

### NON_EVENT_TITLE_RE — the class that must BYPASS the security veto (not be caught by it)
Some mis-rated-High items are non-events whose TITLE carries a security-ish homonym, so the SECURITY_TERM_RE veto (the safety net above) actively RE-ADMITS them: rugby team-selection ("Flying Fijians name powerful side for Wales opener", "Consistency in Selection Ahead of Blackhawks Clash" — `clash`), development-policy essays ("everyday crime and insecurity in PNG - Devpolicy", "Does extreme rainfall trigger tribal violence in PNG? - Devpolicy" — `crime`/`violence`), and an "awareness initiative" community rally writeup. `isDevelopmentWireItem` therefore tests `NON_EVENT_TITLE_RE` FIRST on `title+summary` and drops at ANY severity, deliberately BEFORE and BYPASSING the veto. Anchors are narrow, title-based, and structural: `devpolicy|development policy centre|everyday crime and insecurity|name[sd]? (a )?(powerful )?side|consistency in selection|selection ahead of|awareness (initiative|campaign|programme|program|drive|week|month)`.
**Why:** these are genre/round-up/sports-selection non-events, not security incidents; the veto is correct for real Low crime rows but wrong for a title that IS the non-event. Bypassing it for this narrow set is safe precisely because the anchors are specific phrases, not bare security words.
**How to apply:** grow `NON_EVENT_TITLE_RE` ONLY with distinctive non-event phrases proven not to collide with real events — verify with a live-DB replay over all PNG rows (the fix was proven: 6/6 in-window targets drop, 0 of 76 genuine Moderate+ PNG events lost). DELIBERATELY EXCLUDED the "trained to stop <crime>" awareness-training class — too close to real enforcement copy; that one belongs in the ingest classifier, not a title bypass. This stays DISPLAY-only (no version bump); the durable root cause is upstream severity misclassification (the 7 rows still read High on Protests monitor / flashpoint / dashboard until the ingest classifier is fixed with a version bump + backfill).
